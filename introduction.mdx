## How it works

```
Your system  →  POST /ingestion/transaction
                        ↓
              Detection rules + ML scoring
                        ↓
              Risk score 0-300, three layers
                        ↓
              ALLOW / FLAG / STEP_UP / HOLD / BLOCK
                        ↓
              Alert  →  Case  →  STR/CTR  →  goAML XML
```

Scoring is asynchronous and completes in seconds. Ingestion returns immediately with a transaction id; you learn the outcome by reading [alerts](/api-reference/alerts) or by receiving a [webhook](/guides/webhooks).

---

## What it does

| | |
|---|---|
| **Ingestion** | REST single and batch (up to 1,000), Kafka, USSD fast-path |
| **Detection** | 15 anomaly rules plus 103 production rules |
| **ML scoring** | Gradient-boosted ensemble with an online learner |
| **Decisions** | ALLOW / FLAG / STEP_UP / HOLD / BLOCK, with PEP and FATF overrides |
| **Casework** | Alerts → cases → STR/CTR drafts → goAML XML, with four-eyes approval |
| **Screening** | Sanctions, PEP and adverse information via OpenSanctions |
| **Jurisdictions** | Ghana (primary), Nigeria, Kenya |

## Base URL

```
https://monitor.agregartech.com/api/v1
```

Everything except `GET /health` requires authentication. Start with [Authentication](/authentication) — an API key alone will not read transactions back, and that trips most integrations up on day one.
