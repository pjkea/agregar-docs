title: Quickstart
description: "Send a transaction and see what the engine did with it"

You need an API key. Everything below is copy-paste runnable.

<Warning>
  `timestamp` must be UTC, not in the future, and **not older than 90 days** — otherwise you get `400 timestamp ... is older than 90 days`. The examples generate it, so they cannot go stale.
</Warning>

<Steps>
  <Step title="Check the API is up">
    ```bash
    curl https://monitor.agregartech.com/api/v1/health
    ```

    No authentication needed. Returns `200` with `{"status": "healthy", ...}`.
  </Step>

  <Step title="Send a transaction">
    ```bash
    curl -X POST https://monitor.agregartech.com/api/v1/ingestion/transaction \
      -H "X-API-Key: $API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "customer_id": "CUST001",
        "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
        "amount": 5000.00,
        "transaction_type": "Transfer",
        "channel": "Momo",
        "receiver_id": "CUST002",
        "receiver_country": "GH"
      }'
    ```

    **`201 Created`:**

    ```json
    {
      "success": true,
      "transaction_id": "TXN-64B8F6BA3B2B",
      "message": "Transaction ingested successfully",
      "queued_for_processing": true,
      "is_duplicate": false
    }
    ```

    Required fields are `customer_id`, `timestamp`, `amount`, `transaction_type` and `channel`. Transfers also need `receiver_id`. Scoring runs asynchronously and completes in seconds, so `combined_risk_score` is `null` here.
  </Step>

  <Step title="Trigger something">
    An everyday payment will not alert. To see the engine work, send one that should: a large cross-border transfer from a new customer.

    ```bash
    curl -X POST https://monitor.agregartech.com/api/v1/ingestion/transaction \
      -H "X-API-Key: $API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "customer_id": "CUST999",
        "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
        "amount": 185000.00,
        "transaction_type": "Transfer",
        "channel": "Momo",
        "receiver_id": "CUST002",
        "receiver_country": "AE",
        "is_rooted": true
      }'
    ```
  </Step>

  <Step title="Read the alert">
    ```bash
    curl "https://monitor.agregartech.com/api/v1/alerts?customer_id=CUST999&page=1&page_size=5" \
      -H "X-API-Key: $API_KEY"
    ```

    <Note>
      Filter alerts by `customer_id`, not by transaction id — there is no `transaction_id` filter, and an unknown query parameter is ignored rather than rejected, so you would silently get every alert.
    </Note>

    Each alert carries the score, the band, and which rules fired. See [Alerts](/api-reference/alerts).
  </Step>
</Steps>

## Validate before you send

Check a payload against the schema without storing anything. Useful while you are mapping your fields.

```bash
curl -X POST https://monitor.agregartech.com/api/v1/ingestion/validate \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "CUST001",
    "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
    "amount": 5000.00,
    "transaction_type": "Transfer",
    "channel": "Momo",
    "receiver_id": "CUST002"
  }'
```

## Batch

Up to 1,000 transactions per call. `source_system` is **required**.

```bash
curl -X POST https://monitor.agregartech.com/api/v1/ingestion/batch \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "source_system": "core_banking",
    "transactions": [
      {
        "customer_id": "CUST001",
        "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
        "amount": 1000.00,
        "transaction_type": "Deposit",
        "channel": "Bank"
      }
    ]
  }'
```

```json
{
  "total_submitted": 1,
  "successful": 1,
  "failed": 0,
  "failed_items": [],
  "batch_id": "BATCH-4AB5022B-607"
}
```

Rows are independent: valid ones are stored even if others fail, and `failed_items` says why per row. Track progress with `GET /ingestion/batch/{batch_id}/status`.
